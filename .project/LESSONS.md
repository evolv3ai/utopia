# Lessons

- 001-token-review-skeleton — A task that adds a migration file must also bump `CURRENT_SCHEMA_VERSION` in `crates/utopia-cli/src/main.rs` (it is the count of migration files) and run `cargo test -p utopia-cli` in its Verify; the first project Verify failed on this and cost a patch wave.
- 001-token-review-skeleton — On this Windows host a Verify must build into its own empty Rust build directory outside the worktree (`CARGO_TARGET_DIR`): a directory shared between worktrees served stale artifacts, and build output inside a verify sidecar blocks its cleanup.
- 001-token-review-skeleton — The project Verify needs `pg_dump` and `pg_restore` 16 on PATH and must run the `utopia-store` tests on their own freshly migrated database; `intake_runs_while_model_work_holds_every_slot` times out behind the jobs the server tests leave queued.
- 002-token-review-reads — When a milestone opens something an earlier milestone or wave refused, the planner must search every existing test for assertions of that refusal (for example `unknown_queue`, a 422 on a queue name) and put each such file in the opening task's `files`, with no later Verify freezing it; T002 stopped twice on tests in `review_totals_tests.rs` and `review_attribution_tests.rs` that pinned refusals it had to remove, and T003's Verify needed the same repair.
- 002-token-review-reads — A task that changes behaviour an earlier same-milestone task's Verify pins should declare `supersedes` and carry the earlier Verify's remaining checks in its own; otherwise the regression rerun at landing blocks on the pinned behaviour.
- 002-token-review-reads — On this host a Verify that uses `tee /dev/stderr` needs the `tee` shim directory first on PATH, and `psql` options must come before the connection string (Windows `psql` 16 ignores options placed after it and waits on stdin).
- 003-gated-merge-proposals-revert-batch — When a task adds a field to a shared struct, a variant to a shared enum, a parameter to a tool schema or an entry to an exact list, the planner must search the whole workspace for every full struct literal, exhaustive `match` and exact-shape assertion that the change breaks, and put each such file in that task's `files`; T004 stopped on two `ReviewItem` literals in test helpers and T005 needed `review_token_revert_tests.rs` for one schema assertion.
- 003-gated-merge-proposals-revert-batch — An edge ruling that says "returns to its state" must be checked against the existing undo code before intent approval: T001 found that the existing merge copies `typed_fact_sources` links the existing revert never removes, which cost a build recovery (INTENT correction C1).
- 003-gated-merge-proposals-revert-batch — A brief repair must be committed before the task is activated: the landing reads the allowed file list from the committed brief, so a file added after activation is refused at landing. Use the Edit tool for the repair; inline scripts with backticks or backslashes are refused by the guard or fail silently in a chain.
- 003-gated-merge-proposals-revert-batch — A Verify's module filter must be the mounted module path (for example `review_routes::attribution_tests::`, not the file name `review_attribution_tests::`); a filter that matches no test passes silently.
