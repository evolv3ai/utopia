# T002 — Open the eleven queue sections, the Decisions history and both proof reads to personal tokens over the HTTP API

## Context

After M001 a personal token lists only Duplicates and the Overview summary: `review_ops::list` refuses every other section with `unknown_queue`, and `review_routes::history` (Decisions), `graph_routes::blocked_proof` and `graph_routes::derived_proof` take `AuthUser`, so a token gets 401. The settled design: tokens read the thirteen sections through the three handlers the Review tab already uses — `GET /kbs/{id}/review?queue=` for the eleven queue sections (`pending`, `duplicates`, `conflicts`, `unconfirmed`, `lowconf`, `violations`, `defects`, `alignment`, `errata`, `agent`, `merges`), `GET /kbs/{id}/review/summary` for Overview, `GET /kbs/{id}/review/history` for Decisions — with no new list route per section. Handlers change extractor from `AuthUser` to `SessionOrToken` in place; a session caller's branch runs today's code; a token caller passes the reader check (owner at least Viewer, base inside `kb_ids`, else 404; a dead token gets 401). Each read is one function in `review_ops` taking the resolved caller, so T003's MCP tools call the same functions. `mappings` is a list queue but not a Review section and stays refused for a token. T001 put the queue page with its `total` in `review_routes::queue_page` and built the thirteen-section seed. No Review write is added.

## Approach

- Start with the walking skeleton: one non-Duplicates queue (for example `conflicts`) listed by a read token of a Viewer through `review_ops::list`, equal to the session's body, with a test; then widen to the rest.
- `review_ops::list`: after `authorize_read`, the eleven section names above return `queue_page`'s value unchanged; `mappings` and every other name return the existing `unknown_queue` error and no items. `overview` and `decisions` are not list queues: on the list route they answer `unknown_queue` for a token exactly as they do for a session, and are read through `summary` and `history`. Signature unchanged. Do not copy the queue `match` into `review_ops`.
- `review_routes::history` takes `SessionOrToken`; the token branch calls the new `review_ops::history`; the session branch is today's statements with `caller.user`. Decisions keeps its own `page`/`per` (default 20, clamp 1..=100) and its `{events, total}` body, and its four action families; nothing in `audit::review_history` changes.
- `graph_routes::blocked_proof` and `graph_routes::derived_proof` take `SessionOrToken`; a token passes the same reader check as the list (404 when the owner is below Viewer or the token's `kb_ids` exclude the base) and receives exactly the body the session receives (`{"steps": …}`, `{"proof": …}`). `blocked_proof`'s token branch calls `review_ops::violation_proof` (T003 needs it); for `derived_proof` either a `review_ops` function or the reader check its neighbour `fact_evidence` uses (`require_reader_kb`) is acceptable. The session branches are unchanged.
- N3 (judgment prohibition, SC3). Must not: return through `review_item` or an opened proof read anything a signed-in Viewer of that base could not read through the existing routes. Detail: the reviewer checks that every item and proof read passes the same reader check as the list (owner at least Viewer, base inside `kb_ids`) and returns only fields the session routes already return for that item. So every new read authorizes through `authorize_read` (or `require_reader_kb`, which is the same check) before any store call, and returns the session route's body, not a wider one.
- N4 (judgment prohibition, SC1). Must not: make any Review write other than the M001 keep reachable by a token. Detail: the reviewer checks that this milestone adds no token branch to a write handler and no MCP write tool, and that reading "Awaiting your nod" gives a token no way to nod. Only `history`, `blocked_proof` and `derived_proof` change extractor. Every write handler in `review_routes.rs` keeps the extractor it has (`decide_pending`, `pending_for_chunk`, `agent_answer`, `batch`, the fact, conflict, mapping, violation, defect, alignment-phrase, alignment-rule, errata, consistency and inference handlers stay `AuthUser`); `decide` still opens only `keep`; `crates/utopia-server/src/api/mcp.rs` and `review_tools.rs` are not edited.
- The MCP endpoint's HTTP 403 for a token whose `kb_ids` exclude the base is vetoed from change (INTENT Scope out, driver D074): do not touch `mcp::authorize`. The E12 test only observes it.
- Two M001 tests assert the refusal this task narrows. In `review_token_api_tests.rs` remove `a_token_asking_for_another_section_is_refused_with_unknown_queue`; its replacement is the E4 test of this task. In `review_mcp_tests.rs` the test `review_list_refuses_another_section_with_unknown_queue` becomes `review_list_refuses_mappings_and_an_unknown_section_with_unknown_queue`, asserting the refusal for `mappings` and for a made-up name only. Change nothing else in those two files; the MCP tool descriptions are T003's.
- Tests go in the new `crates/utopia-server/src/api/review_token_reads_tests.rs`, declared in `mod.rs`, through the router with `Fx` (`review_session_unchanged_tests.rs`) and `seed_every_section` (`review_totals_tests.rs`). For E13 seed governor rows as `review_attribution_tests.rs` does (direct `agent_decisions` inserts) on a base without a token action. For the clamp, more than 200 rows are needed in one section; pending pairs through `Fx::pair` are the cheap way. Do not edit `review_session_unchanged_tests.rs`, `review_totals_tests.rs`, `review_attribution_tests.rs` or any store test.
- Conventions (bind this task): explanatory code comments in Chinese that say why, updating the module comments that say only Duplicates is open; test functions named as sentences; user-facing error strings in English with a stable `code`; ADR 0076 covers these reads and is amended by T004; no migration; one behaviour-sentence commit subject with a DCO `Signed-off-by`; `cargo fmt` clean in the files this task lists and no formatting of files it does not; nothing is sent to `deeplethe/utopia` or a deployed instance.

## Interface contract

- `crate::api::review_routes::queue_page` (file `crates/utopia-server/src/api/review_routes.rs`): `pub(super) async fn queue_page(state: &AppState, kb_id: Uuid, queue: &str, types: Option<&str>, limit: Option<i64>, offset: Option<i64>) -> Result<serde_json::Value, utopia_core::AppError>`. It does no authorization. For the twelve list queues `pending`, `duplicates`, `conflicts`, `unconfirmed`, `lowconf`, `mappings`, `alignment`, `errata`, `violations`, `defects`, `merges`, `agent` it returns `{"counts": <ReviewCounts>, "queue": "<queue>", "items": [...], "total": <integer>}`: `counts` and `items` are what the session list route returns at commit `904b2a2` for the same arguments (limit default 10, clamped to 1..=200; offset floored at 0; `types` applies to `duplicates` only), and `total` is the number of rows that queue's list returns over all pages for the same `types`. Any other queue name returns `AppError::invalid("unknown_queue", "no review queue named <queue>")`.
- Session and token list response: `GET /api/v1/kbs/{kb_id}/review?queue=<queue>&types=&limit=&offset=` answers `{"counts","queue","items","total"}`; `total` is an integer, the only key added to the response of commit `904b2a2`.
- Section seed: file `crates/utopia-server/src/api/review_totals_tests.rs`, `pub(super) async fn seed_every_section(f: &super::review_session_unchanged_tests::Fx) -> anyhow::Result<()>`. After it returns, base `f.kb` holds at least two listed items in each of `pending`, `duplicates`, `conflicts`, `unconfirmed`, `lowconf`, `violations`, `defects`, `errata`, `merges` and `agent`, at least one proposed mapping, and in `alignment` at least two phrases, one kind word and two proposed implication rules, one of which is last in the list order; `lowconf` holds at least one derived fact (`derived_by_rule` not null) and one that is not; `violations` holds one item of kind `derived_contradiction` for which `utopia_store::reasoning::blocked_proof` returns at least one step and one item of another kind; `agent` holds at least one governor row and exactly one token row, a keep made with a write token of `f.editor`; the Decisions history holds at least two events. Base `f.other_kb` is not touched.
- `crate::api::review_ops` reads (file `crates/utopia-server/src/api/review_ops.rs`), each authorizing inside itself and returning `AppError::NotFound` when the owner is not at least Viewer of the base or the token's `kb_ids` exclude it: `pub(crate) async fn list(state: &AppState, caller: &ReviewCaller, section: &str, types: Option<&str>, limit: Option<i64>, offset: Option<i64>) -> Result<serde_json::Value, AppError>` returns `{"counts","queue","items","total"}` for the eleven sections `pending`, `duplicates`, `conflicts`, `unconfirmed`, `lowconf`, `violations`, `defects`, `alignment`, `errata`, `agent`, `merges` and `AppError::invalid("unknown_queue", ..)` for `mappings` and every other name; `pub(crate) async fn history(state: &AppState, caller: &ReviewCaller, page: Option<i64>, per: Option<i64>) -> Result<serde_json::Value, AppError>` returns `{"events": [...], "total": <integer>}` as `GET /review/history` returns it to a session (`page` default 0, floored at 0; `per` default 20, clamped to 1..=100); `pub(crate) async fn violation_proof(state: &AppState, caller: &ReviewCaller, violation_id: Uuid) -> Result<serde_json::Value, AppError>` returns `{"steps": <array or null>}` as `GET /violations/{violation_id}/proof` returns it to a session; `summary` is unchanged from M001.
- Token-open Review reads, all under `/api/v1` with `Authorization: Bearer utp_pat_…`, any scope, owner at least Viewer: `GET /kbs/{kb_id}/review?queue=<one of the eleven sections>` (optional `types` for `duplicates`, `limit`, `offset`), `GET /kbs/{kb_id}/review/summary`, `GET /kbs/{kb_id}/review/history?page=&per=`, `GET /kbs/{kb_id}/violations/{violation_id}/proof`, `GET /kbs/{kb_id}/derived/{derived_id}/proof`. Refusals: 401 for a dead or revoked token; 404 when the owner is below Viewer or the token's `kb_ids` exclude the base; 422 with code `unknown_queue` on the list route for `mappings` or any name that is not one of the eleven.

## Acceptance criteria

1. SC1: test `a_read_token_of_a_viewer_lists_each_of_the_thirteen_sections_as_a_session_editor_sees_them` — on the seeded base a read-scope token whose owner is a base Viewer gets 200 for each of the eleven queue sections, for the Overview summary and for the Decisions history, and each body equals what the signed-in editor gets for the same request (`counts`, `queue`, `items` and `total`; the whole summary; `events` and `total`), with at least one item in every section.
2. E1 (held-out; ruling: for a section with no items a token gets an empty list and total 0, the same as a signed-in editor, not an error): test `an_empty_section_reads_as_an_empty_list_with_total_0_for_a_token_as_for_a_session` shows, on a base with nothing seeded, 200 with `items: []` and `total: 0` for each of the eleven queues and `events: []` with `total: 0` for Decisions, equal for the token and the session.
3. E2 (held-out; ruling: a token receives a section's items in the order the session list returns for the same request): test `a_token_receives_each_sections_items_in_the_session_order` compares, for each of the eleven queues over two pages (`limit=1`, offsets 0 and 1) and for Decisions (`per=1`, pages 0 and 1), the identifier sequence of the token's and the session's responses.
4. E3 (held-out; ruling: the list queues keep the existing clamp — a page size below 1 is served as 1 and above 200 as 200; an offset at or past the total returns no items and the true total): test `a_token_page_size_is_clamped_and_an_offset_at_or_past_the_total_returns_no_items` shows one item for `limit=0` and `limit=-5` on each of the eleven queues, 200 items for `limit=201` and `limit=1000000` on a section holding more than 200 rows, and for an offset equal to `total` and one beyond it `items: []` with the unchanged `total`, none of them an error.
5. E4 (held-out; ruling: a section name outside the thirteen, including `mappings`, is refused with the existing `unknown_queue` coded error and returns no items): test `a_token_asking_for_mappings_or_an_unknown_section_is_refused_with_unknown_queue` shows 422 with code `unknown_queue` and no `items`, `total` or `counts` for `queue=mappings` and a made-up name, on a base that has a proposed mapping, while the session editor still lists `mappings`. Over MCP the changed test `review_list_refuses_mappings_and_an_unknown_section_with_unknown_queue` shows the same refusal as a tool error.
6. E5 (held-out; ruling: `total` is the number of rows the section's list returns over all pages; for Low confidence it counts the listed rows, derived facts included; for Agent History it counts rows of both sources; the existing `counts` keys keep today's values): test `a_tokens_total_counts_the_listed_rows_and_counts_keep_their_values` shows, for a token on the seeded base, that paging each of the eleven queues to the end returns exactly `total` rows; that the Low confidence `total` includes the derived fact while `counts.lowconf` does not; that the Agent History `total` is the number of governor rows plus ledger rows while `counts.agent` stays the badge value; and that `counts` equals the session's.
7. SC4 with E10: test `a_token_paging_alignment_by_the_total_reaches_the_last_implication_rule` — a token reads `total` from `queue=alignment`, pages with `limit=1` from offset 0 to `total − 1`, receives one item at every offset, sees every proposed implication rule of the seed, and receives the rule that is last in the order at offset `total − 1`; `counts.alignment` is lower than `total` by the number of rules.
8. E11 (held-out; ruling: the Alignment list gains an id tie-break in its order, so a client paging by `limit` and `offset` over an unchanged queue visits each waiting item exactly once): test `a_token_paging_alignment_with_equal_timestamps_visits_each_waiting_item_exactly_once` sets one `decided_at` on every waiting Alignment item and shows a token paging with `limit=1` and with `limit=2` receives each item's identifier exactly once.
9. SC5: test `a_token_whose_kb_ids_exclude_the_base_gets_404_on_every_review_read` — a token of a base member whose `kb_ids` exclude the base gets 404 on each of the eleven queue lists, the summary, the history and both proof routes, and each body equals the body the same token gets for a base id that does not exist, with no `items`, `total`, `counts`, `events`, `steps` or `proof` in it. The M001 tests `a_token_whose_kb_ids_exclude_the_base_gets_404_on_review_reads` and `a_token_whose_kb_ids_exclude_the_base_reads_no_review_data_over_mcp` pass unchanged.
10. E12 (held-out; ruling: a dead or revoked token gets 401 on the token API and on the MCP endpoint; a token whose `kb_ids` exclude the base gets 404 on the token API and the MCP endpoint's existing HTTP 403 before any tool runs, with no item, count or evidence in the answer): test `a_dead_token_gets_401_and_an_excluded_token_gets_404_on_the_api_and_403_on_the_mcp_endpoint` shows 401 for a revoked token on a queue list, the summary, the history, a proof route and a `tools/call` of `review_list`; and for the excluded token 404 on those REST reads and HTTP 403 on `tools/list` and on `tools/call` of `review_list` and `review_item`, with none of `items`, `total`, `counts`, `events` or evidence in any of those bodies. `crates/utopia-server/src/api/mcp.rs` is unchanged from `904b2a2`.
11. SC6: test `agent_history_read_by_a_token_names_the_owner_and_the_token_of_a_keep_beside_governor_rows` — a read token lists `queue=agent` on the seeded base and receives the M001 keep as a row with `source: "token"`, `operation: "review.keep"`, the owner's `owner_name` and the token's `token_name`, beside governor rows that carry no `source` key; the body equals the session editor's.
12. E13 (held-out; ruling: on a base with no token action a token reads the governor's rows only, exactly as the session list; the ledger row's token name is the snapshot stored with the action): test `agent_history_without_a_token_action_reads_governor_rows_only_and_a_ledger_row_keeps_its_stored_token_name` shows, on a base with governor rows and no token action, a token body equal to the session's with no `source: "token"` row and `total` equal to the number of governor rows; and, after a keep followed by a rename of the keeping token, a `token_name` that is still the name the token had at the keep.
13. Test `a_read_token_of_a_viewer_reads_both_proof_routes_as_a_session_does`: the token's `GET /violations/{id}/proof` equals the session's for the seeded `derived_contradiction` item (non-empty `steps`) and for an item of another kind (`{"steps": null}`), and `GET /derived/{id}/proof` equals the session's for the seeded derived fact and for a made-up id.
14. Test `a_token_cannot_nod_and_no_review_write_but_keep_answers_a_token`: a write token of an editor gets 401 on `POST /kbs/{kb}/review/pending/{pending_id}` for a listed pending item and the item is still listed; it gets 401 on the batch and governor-answer routes; and the M001 test `a_refused_token_merge_revert_or_batch_leaves_the_graph_equal` passes unchanged. `git diff` of this task shows an extractor change on `history`, `blocked_proof` and `derived_proof` only.
15. The session test `a_session_editor_gets_todays_duplicates_overview_keep_merge_and_batch_responses` passes; `review_session_unchanged_tests.rs`, `review_totals_tests.rs` and `review_attribution_tests.rs` are not edited; `cargo fmt --all --check` reports nothing in the files this task lists.
