# T004 — Open Duplicates, Overview and keep to personal tokens over the HTTP API through one shared operation layer

## Context

Every handler in `crates/utopia-server/src/api/review_routes.rs` takes `AuthUser` (session only) except `decide_alignment_kind_word`, so a personal token gets 401 on Review. The settled design: the existing handlers change extractor from `AuthUser` to `SessionOrToken` in place (same URLs, no parallel route tree); a session caller runs today's code unchanged; a token caller is passed to one server function per Review operation that takes the resolved caller (owner, token, base) and holds authorization, policy, ledger and audit in one place, so that the MCP tools of T005 call the same functions. In this milestone a token reads Duplicates (`GET /kbs/{id}/review?queue=duplicates`) and Overview (`GET /kbs/{id}/review/summary`) at owner role Viewer, and keeps one duplicate pair (`POST /kbs/{id}/review/{review_id}`, action `keep`) with scope `write` and an owner at least Editor. The store side exists from T003: `keep_duplicate_pair` writes the review row, the ledger row and the audit row in one transaction, and `agent_policy` holds the owner's ruled table. ADR 0076 (T002) records the routes and codes.

## Approach

- New module `crates/utopia-server/src/api/review_ops.rs`, declared in `crates/utopia-server/src/api/mod.rs`. The server crate has no `lib.rs`; tests are sibling `*_tests.rs` files in `src/api/`, wired with `#[cfg(test)] #[path = "..."] mod ...;` in `review_routes.rs` or `review_ops.rs` (as `review_routes.rs` already does for its phrase and conflict tests) or declared in `mod.rs`.
- Handlers that change extractor: `list`, `summary`, `decide`. Each branches on `caller.pat`: `None` runs the body that is there today, statement for statement, with `caller.user`; `Some(pat)` builds a `ReviewCaller` and calls the `review_ops` function. Do not route the session branch through `review_ops`.
- Every other handler in the file keeps `AuthUser`, so a token still gets 401 there: `batch`, `revert_merge`, `manual_merge`, `agent_answer`, `history`, `decide_pending`, `pending_for_chunk`, the fact, conflict, mapping, violation, defect, alignment-phrase, alignment-rule, errata, consistency and inference handlers. `decide_alignment_kind_word` is not touched.
- Read checks are those of `documents_routes::require_reader_kb` (`crates/utopia-server/src/api/documents_routes.rs`): owner at least Viewer, and 404 when the token's `kb_ids` exclude the base — the same answer as for a base that does not exist (INTENT prohibition N2).
- Write checks follow the order `decide_alignment_kind_word` already uses: `SessionOrToken::require_write(Some(kb_id))` semantics first (`token_read_only`, then `token_kb_out_of_scope`, both existing `CodedForbidden` in `crates/utopia-server/src/auth.rs`), then the owner's role. Today a below-Editor owner gets a plain 403 from `require_kb`; for a token caller it must be `AppError::CodedForbidden { code: "token_owner_below_editor", .. }`. A session caller's 403 stays as it is.
- The token branch of `decide`: action `keep` goes to `review_ops::keep`; any other action is refused with `AppError::CodedForbidden { code: "token_operation_not_open", .. }` after the scope and role checks, and nothing is written. `review_ops::keep` asks `utopia_store::execution_gate::agent_policy(AgentOperation::Keep, None)` and applies only on `Applied`; any other outcome is the same `token_operation_not_open` refusal in this milestone.
- The token branch must not call `crate::governance::after_human_decision`: a token decision starts no govern round and settles no governor proposal. It does call `state.emit_review(kb_id)` so an open Review tab refreshes.
- A token asking `list` for any queue other than `duplicates` gets the existing `unknown_queue` coded error from `review_ops::list` and no items; the other eleven sections stay closed to tokens in this milestone. The `types` filter of Duplicates is served as for a session.
- "Same items and counts as a signed-in editor" is safest when both branches call the same store functions with the same clamp: `utopia_store::review::counts`, `utopia_store::resolution::list_reviews` with `TypeFilter::parse`, `utopia_store::review_summary::summary`, limit default `REVIEW_PAGE` clamped to 1..=200, offset floored at 0.
- Write `review_session_unchanged_tests.rs` first, against the handlers as they are at your base, and see it pass before you change an extractor: it pins the session responses this task must not change. Session callers in tests are made as `review_routes_phrase_tests.rs` makes its editor; token callers as `token_read_tests.rs` and `token_setup_tests.rs` do (`utopia_store::tokens::issue`, requests through `super::router(state, &cfg)` with `tower::ServiceExt::oneshot`). Seed pending pairs directly in `resolution_reviews` with entities of the test's own base; tests build and remove their own base.
- Documentation: add to `web/src/docs/mcp.md` a section on the Review routes a token can call (the two reads, the keep, who may call them, every refusal code and status, the statement that the other sections and merge, revert and batch are not open to tokens). The server embeds this file at compile time (`crates/utopia-server/src/docs_corpus.rs`), so the Verify rebuilds the server and runs the corpus test.
- Not in this task: any MCP tool (T005), Agent History or Activity (T006), any change to `crates/utopia-server/src/api/mcp.rs`, any change to the `remember` path.
- Conventions (bind this task): explanatory code comments in Chinese; tests and migrations named as sentences; user-facing error strings in English with a stable `code`; an ADR precedes any public-API or data-model change (ADR 0076 from T002 covers these routes; if a route or code must differ from it, stop with `NEEDS-ORCHESTRATOR`); new migration numbers start at 0128 and ADR numbers at 0076, re-checked against upstream `deeplethe/utopia` `dev` and its open pull requests before landing — this task adds no numbered file; migration SQL idempotent; one behaviour-sentence commit subject with a DCO `Signed-off-by`; nothing is sent to `deeplethe/utopia` or a deployed instance.

## Interface contract

- `utopia_store::execution_gate` (file `crates/utopia-store/src/execution_gate.rs`): `pub enum AgentOperation { ConfirmFact, RejectFact, CloseFact, Merge, Keep, RevertMerge, ResolveConflict, PendingNod, Batch, AnswerGovernor, AlignmentPhrase, AlignmentRule, AlignmentKindWord, Errata, OntologyProposal, Mapping, Violation, Defect, ConsistencyRun }`; `pub enum AgentRuling { Finalize, FinalizeBehindGate, ProposeOnly }`; `pub enum AgentOutcome { Applied, Held, Proposed }` with `pub fn as_str(&self) -> &'static str` returning `"applied"`, `"held"`, `"proposed"`; `pub fn agent_ruling(op: AgentOperation) -> AgentRuling`; `pub fn agent_policy(op: AgentOperation, hold: Option<&Hold>) -> AgentOutcome`, where `Finalize` gives `Applied`, `FinalizeBehindGate` gives `Applied` when `hold` is `None` and `Held` otherwise, and `ProposeOnly` gives `Proposed`.
- `utopia_store::token_agent_actions::TokenAgentAction` (file `crates/utopia-store/src/token_agent_actions.rs`): `pub struct TokenAgentAction { pub id: Uuid, pub kb_id: Uuid, pub operation: String, pub target_kind: String, pub target_id: Uuid, pub owner_id: Uuid, pub owner_name: Option<String>, pub token_id: Uuid, pub token_name: String, pub outcome: String, pub payload: serde_json::Value, pub created_at: DateTime<Utc> }`, deriving `Debug, Clone, Serialize, sqlx::FromRow`; `owner_name` is `users.display_name` joined at read time, `token_name` is the stored snapshot, `payload` is `{"left","right","score","why"}` for a keep.
- `utopia_store::token_agent_actions::keep_duplicate_pair`: `pub async fn keep_duplicate_pair(pool: &PgPool, kb_id: Uuid, review_id: Uuid, owner_id: Uuid, token_id: Uuid, rationale: Option<&str>) -> AppResult<TokenAgentAction>`. In one transaction it sets the `resolution_reviews` row to `status = 'kept'`, `decided_at = now()`, `decided_by = owner_id`, `decided_token = token_id`, `rationale`; inserts one `token_agent_actions` row with `operation = 'review.keep'`, `target_kind = 'review'`, `target_id = review_id`, `outcome = 'applied'`; and inserts one `audit_events` row with action `review.keep`, target kind `review`, target id `review_id`, actor `owner_id` and detail `{"left","right","score","why","token_id","token_name"}`. Errors: `AppError::NotFound` when the base has no review row with that id; `AppError::CodedConflict { code: "already_decided", .. }` when the row is not `pending`; the `AppError::Conflict` of `resolution::decide_review` when the governor holds the pair; any failure to read the token's name or to write the ledger or audit row is an error and nothing is committed.
- `crate::api::review_ops` (file `crates/utopia-server/src/api/review_ops.rs`): `pub(crate) struct ReviewCaller { pub user: utopia_core::models::User, pub token: utopia_store::tokens::Authenticated, pub kb_id: Uuid }`; `pub(crate) async fn list(state: &AppState, caller: &ReviewCaller, section: &str, types: Option<&str>, limit: Option<i64>, offset: Option<i64>) -> Result<serde_json::Value, AppError>`, where section `"duplicates"` returns `{"counts","queue","items"}` exactly as `GET /api/v1/kbs/{kb_id}/review?queue=duplicates` returns it to a session (limit default 10, clamped to 1..=200; offset floored at 0) and any other section returns `AppError::invalid("unknown_queue", ..)`; `pub(crate) async fn summary(state: &AppState, caller: &ReviewCaller) -> Result<utopia_core::models::ReviewSummary, AppError>`; `pub(crate) async fn keep(state: &AppState, caller: &ReviewCaller, review_id: Uuid, rationale: Option<&str>) -> Result<serde_json::Value, AppError>`, returning `{"ok": true, "outcome": "applied", "action_id": "<ledger row id>"}`. Every function authorizes inside itself: `list` and `summary` return `AppError::NotFound` when the owner is not at least Viewer of the base or the token's `kb_ids` exclude it; `keep` checks the token's scope first (`token_read_only`, then `token_kb_out_of_scope`), then the owner's role (`AppError::CodedForbidden { code: "token_owner_below_editor", .. }` below Editor), then the policy, then calls `keep_duplicate_pair`, and does not call `after_human_decision`.
- Token-open REST routes, all under `/api/v1` with `Authorization: Bearer utp_pat_…`: `GET /kbs/{kb_id}/review?queue=duplicates` (optional `types`, `limit`, `offset`), `GET /kbs/{kb_id}/review/summary`, and `POST /kbs/{kb_id}/review/{review_id}` with body `{"action":"keep","rationale":<string or null>}` answering `{"ok": true, "outcome": "applied", "action_id": "<uuid>"}`. Refusals: 404 for a base outside the token's `kb_ids` on the reads; 422 `unknown_queue`; 403 `token_read_only`, `token_kb_out_of_scope`, `token_owner_below_editor`, `token_operation_not_open`; 409 `already_decided`.
- Session regression test: file `crates/utopia-server/src/api/review_session_unchanged_tests.rs`, test function `a_session_editor_gets_todays_duplicates_overview_keep_merge_and_batch_responses`.

## Acceptance criteria

1. SC2: test `a_read_token_of_a_viewer_lists_duplicates_and_overview_as_a_session_editor_sees_them` — on a base with several pending pairs, a read-scope token whose owner is a base Viewer gets 200 on the Duplicates list and on the Overview summary, and the `items` and `counts` of the list and the whole summary body equal what a signed-in editor of the base gets for the same requests. Test `a_token_whose_kb_ids_exclude_the_base_gets_404_on_review_reads` — a token of the same person whose `kb_ids` exclude the base gets 404 on both reads, with no item, count or summary in the body.
2. E3 (held-out; ruling: for a section with no items a token gets the same empty list and zero counts a signed-in editor gets, not an error): test `an_empty_duplicates_section_reads_the_same_for_a_token_and_a_session` shows 200, `items: []` and equal counts for both callers on a base with no pending pair.
3. E4 (held-out; ruling: a token receives a section's items in the same order the session list returns for the same request): test `a_token_receives_duplicates_in_the_session_order` compares the id sequence of the token's and the session's responses for the same `limit`, `offset` and `types`, across two pages.
4. Test `a_token_asking_for_another_section_is_refused_with_unknown_queue`: a token asking for `queue=pending`, `queue=agent` and `queue=merges` gets 422 with code `unknown_queue` and no items, while a session caller still gets those sections.
5. SC6 with E15 (held-out; ruling: "changes nothing in the graph" is checked by reading the base's entities, facts, review rows and merges before and after the refused call and finding them equal): test `a_refused_token_merge_revert_or_batch_leaves_the_graph_equal` — a write token of an editor is refused on `POST /review/{review_id}` with action `merge` (403, code `token_operation_not_open`), on the batch route with action `merge` and with action `keep`, on the merge-revert route and on the manual-merge route (401 each); the rows of `entities`, `facts`, `resolution_reviews` and `entity_merges` of the base, read before and after, are equal, and no `token_agent_actions` row exists.
6. Test `a_write_token_of_an_editor_keeps_a_pair_over_the_api`: the keep answers 200 with `outcome: applied` and an `action_id`; the pair is no longer in the Duplicates list for the token or the session; one ledger row with outcome `applied` and one `review.keep` audit row with `token_id` and `token_name` exist.
7. Test `a_keep_over_the_api_is_refused_with_its_code`: `token_read_only` for a read-scope token, `token_kb_out_of_scope` for a write token whose `kb_ids` exclude the base, `token_owner_below_editor` for a write token of a Viewer, `already_decided` for a repeat; the pair's state is unchanged by each refusal.
8. Test `a_token_keep_over_the_api_starts_no_govern_round`: on a base with governance on, after a token keep no `jobs` row of kind `govern` exists for the base and an open `agent_decisions` proposal on the pair is still `proposed`.
9. Test `a_session_editor_gets_todays_duplicates_overview_keep_merge_and_batch_responses` passes on the handlers before and after this task's change: status and body shape of the session's Duplicates list, Overview, keep, merge and batch responses, the audit rows a session keep writes (no `token_id`), and a session Viewer's plain 403 on keep.
10. `web/src/docs/mcp.md` documents the three token-open Review routes and their refusal codes; the `docs_corpus` test `every_corpus_md_file_is_indexed` passes.
11. `crates/utopia-server/src/api/mcp.rs` is unchanged.
