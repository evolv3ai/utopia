## Finding: F1 — The policy enum already carries every M004 row; three rows rule "finalize" with no caller, and there is no separate inference operation

- **Claim**: `AgentOperation` has nineteen variants including `ConfirmFact, RejectFact, CloseFact, ResolveConflict, PendingNod, AnswerGovernor, AlignmentPhrase, AlignmentRule, AlignmentKindWord, Errata, OntologyProposal, Mapping, Violation, Defect, ConsistencyRun`. `agent_ruling` is a `match` with no wildcard: `Finalize` for `Keep | AlignmentKindWord | Mapping | ConsistencyRun`, `FinalizeBehindGate` for `Merge | RevertMerge | Batch`, `ProposeOnly` for the rest. - **Confidence**: high
- **Why it matters here**: No policy row needs adding for M004 unless inference becomes its own row; a new variant breaks the no-wildcard `match` and the `assert_eq!(all.len(), 19)` test at once.

## Finding: F3 — No store entry lands a propose-only proposal; `held_back` returns an error for a `ProposeOnly` row

- **Claim**: `land_proposal` (one transaction: ledger row + `agent.proposal` audit row; returns the existing open proposal with `existing: true`), `NewRow`, `insert_row` and `open_proposals` are private to `token_agent_actions.rs`. - **Source**: `crates/utopia-store/src/token_agent_actions.rs:330-339, 346-380, 411-430, 434-495`; `docs/decisions/0076-a-token-agent-acts-on-review-under-a-ruled-table.md:3`.
- **Confidence**: high

## Finding: F5 — The answer route dispatches on three operation strings and returns a merge id

- **Claim**: `answer_proposal` matches `p.operation` on `"review.merge"`, `"merge.manual"`, `"merge.revert"` and answers any other operation with `AppError::Other("proposal … has an operation nobody can approve: …")` (HTTP 500). Its result is `(&'static str, Option<Uuid>)` = (closed-as state, merge id); `enum Approved { Done(Option<Uuid>), Gone }`; the response is `{ok, state[, merge_id]}`. "Superseded" is decided by `token_agent_actions::target_gone`, which recognises `NotFound`, a `Conflict` whose text equals `resolution::ALREADY_MERGED`, or "Merge already reverted" — string matches on merge errors only. A decline or supersede writes audit `agent.proposal.declined|superseded` with detail `{agent_proposal, operation, reason, left, right, proposed_by_token}`. Approval is not one transaction with the applied change (ADR known limit).
- **Source**: `crates/utopia-server/src/api/review_routes.rs:599-651, 850-918` (dispatch at `:866-875`), `:921-994`; `crates/utopia-store/src/token_agent_actions.rs:1112-1124`; ADR 0076 `:462-466`.
- **Confidence**: high
- **Why it matters here**: Each new proposable operation needs an approve arm, a rule for "the target can no longer be decided", and a decision on what the answer returns in place of `merge_id`; an unhandled operation in the store today would answer 500 on approve.
